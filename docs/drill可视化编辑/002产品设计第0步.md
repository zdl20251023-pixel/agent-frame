1. 研发可开工最低标准
   先明确产品设计到什么程度，研发可以开始评估和开工。

2. 宣讲前 Checklist
   先把容易导致打回的问题提前检查掉，比如目标、范围、主流程、异常情况、验收标准、研发风险点。

3. 评审后问题记录和反哺方式
   先简单记录为什么被打回、后面怎么改、哪些高频问题要补进 Checklist。复盘和归因先做成简单记录，不先展开成复杂流程。

适用范围我也先收窄，只放在中等及以上复杂度需求；小改动、小配置、小运营需求先不强制套。
