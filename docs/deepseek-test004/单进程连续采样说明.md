# 单进程连续采样：前两张牌169类分布

本次是新采集的数据，不复用或覆盖原有独立进程采样。旧的《169分布图.html》保持不变。

## 采集口径

一个 Node.js 进程连续采集200,000,000手。每手创建新52张牌，使用项目原有 Fisher–Yates 完整洗牌和 `node:crypto.randomInt`，检查整副牌合法性后，记录前两张牌。不在分段边界重新启动进程或重置随机源。

“连续”指同一进程连续执行，并不是把上一手的牌堆接着洗。每手仍遵循原项目创建新牌堆的实现。

| 每段手数 | 轮次 | 如何从1万手基础段合并 |
|---|---:|---|
| 1万 | 20,000 | 每1段 |
| 5万 | 4,000 | 连续5段 |
| 10万 | 2,000 | 连续10段 |
| 50万 | 400 | 连续50段 |
| 100万 | 200 | 连续100段 |

同一档位的各段不重叠、不遗漏。五档使用同一条数据序列，因此1万手×5轮和5万手×1轮的169类累计次数完全相同；五档全部轮次的总结果也完全相同。不能把这五档当作五次独立验证。

## 独立留档

每次采集使用新的 `results/continuous-single/<时间与UUID>/` 目录：

- `run-start.json`：启动时间、唯一运行编号、进程PID、采集规模和源码校验值。
- `blocks.ndjson`：20,000行，每行对应连续1万手，保存169类计数、有效/非法手数、全局起止手号、同一采集PID和两牌明细的定位、校验值。
- `pairs-001.bin`～`pairs-200.bin`：每个文件保存连续100万手的前两张牌。每手2字节，牌编码为 `suit*13+rank`；非法牌堆记录为255、255。总计400,000,000字节，约381.5 MiB。
- `source/`：实际采集工具、洗牌实现、验证计数逻辑的源码副本。
- `manifest.json`：仅在全部2亿手完成后生成，保存结束时间、总手数、文件SHA-256等。没有此文件的目录不作为完整实验结果。
- `invalid.ndjson`：仅发现非法牌堆时产生，保存相关信息。
- `derived/segments-<手数>.json`：五档的连续分段计数，可从原始记录重新生成；`index.json`保存来源和校验值。

每1万手写入一次结果，每100万手关闭一个两牌文件；不把2亿手同时放进内存。二进制文件按100万手拆分只是存储安排，不会重启采集进程。

## 报告操作

新报告为《单进程连续采样169分布图.html》。沿用偏差百分比／z-score两种角度、固定百分比颜色刻度、动态波动参考、单格计算说明及NIST来源链接。

切换档位保留累计轮次；若超出新档上限，则取新档全部轮次。可点击“全部轮次”，直接输入轮次或用滑块选择。

格子弹窗显示累计实际次数和理论次数，并按连续200轮分页展示每轮的实际／理论折线及次数列表。分页不抽点、不平滑；同一累计范围内翻页保持纵轴一致。可直接跳到任意轮，也可下载所选牌型前N轮的完整次数CSV。页面始终标明当前展示范围，避免把分页误认为全部结果。

z参考假设各手独立且理论概率正确。一个进程采集本身不能证明各手独立；单项越过3σ只提示关注，不直接判定算法异常。

## 执行与复算

以下命令在本目录执行。采集命令每次都会产生一套全新的数据，不用于调整页面：

```powershell
node src/continuous-run.ts
```

后续仅更新报告，无需重新采样：

```powershell
node src/continuous-report.ts results/continuous-single/<运行目录>
```

报告生成器先核对源码和数据文件SHA-256，再从全部两牌明细复算每1万手169类计数，确认起止编号、进程PID、合计一致，随后生成五档合并计数和新HTML。它不会修改原始计数或二进制文件。

`results/continuous-single/preserved-existing.json`记录本次开始前2,042个旧数据与旧报告文件的SHA-256，用于核实旧文件保持不变。
