# 独立进程分段对比：前两张牌169类分布

## 要回答的问题

一次启动后的前1万手里AA偏多，不代表每次启动都这样。本实验重新启动2,000个子进程，分别观察启动后的第1段、第2段，直到第10段，检查同一段的偏差是否在不同进程中反复出现。

这是新实验，不复用旧采样。原有数据、采样说明和HTML保持不变。

## 采集规则

- 新启动2,000个独立子进程，最多同时运行4个。
- 每个子进程连续跑100,000手，顺序分为10段，每段10,000手。
- 第1段从进程生成的第一手开始，不丢弃“预热”手数。段与段之间不重启进程、不主动重置随机源。
- 每手仍使用项目原有实现：创建新52张牌，使用 `node:crypto.randomInt` 完成 Fisher–Yates 全副洗牌，验证整副牌合法，再统计前两张牌的169类。
- 总量：2,000×100,000＝200,000,000手。
- 进程逻辑编号在采样前分配，按1～2,000累计，不按完成先后或统计结果重新排序。
- 每次启动分配唯一UUID，并保存操作系统PID、时间和退出状态。操作系统可能复用已退出进程的PID，不能据此把两次启动当成同一个进程。

## 按段纵向统计，绝不跨段累加

| 页面选择 | 每个进程中取哪些手 | 累计全部2,000个进程 |
|---|---|---:|
| 第1段 | 第1～10,000手 | 20,000,000手 |
| 第2段 | 第10,001～20,000手 | 20,000,000手 |
| 第3段 | 第20,001～30,000手 | 20,000,000手 |
| 第4段 | 第30,001～40,000手 | 20,000,000手 |
| 第5段 | 第40,001～50,000手 | 20,000,000手 |
| 第6段 | 第50,001～60,000手 | 20,000,000手 |
| 第7段 | 第60,001～70,000手 | 20,000,000手 |
| 第8段 | 第70,001～80,000手 | 20,000,000手 |
| 第9段 | 第80,001～90,000手 | 20,000,000手 |
| 第10段 | 第90,001～100,000手 | 20,000,000手 |

选择第10段不是累计第1～10段。十张169分布视图的记录、计数、累计计算和详情分别处理。

例如，第1段＋前100个进程，只加这100个进程各自第1段，共100万手；切换第10段，使用同样100个进程各自第10段，也是100万手，但是另一组记录。

“分开统计”不等于已经证明同一进程内的不同段没有统计关联。

## 新报告

文件：`独立进程分段对比169分布图.html`。

- 顶部选择第1～10段，替代原来的手数档位。
- 累计数量就是子进程数量，范围1～2,000。支持滑动、手动输入、快捷增加和全部选择。切换段保留数量。
- 保留偏差百分比和z-score两种角度。百分比颜色使用原报告的固定刻度，z参考按当前所选段的累计合法手数计算。
- 点击格子查看累计次数、理论次数、偏差、波动参考和NIST依据。
- 折线与列表只展示所选段在各个进程中的次数，每页最多200个进程，不抽点、不平滑。可直接跳到任意进程，底部显示其本段明细和PID。
- 可下载所选牌型、所选段、前N个进程的完整次数CSV。

观察时既看单个进程中的偏多、偏少，也看多个进程合计后的偏差幅度。z参考以各手独立且理论概率正确为前提；超过3只提示关注，不等于发现算法异常。反复查看169类、十个段和多个累计数量，也可能遇到偶然越线。

## 单独留档

每次运行使用新的 `results/startup-segments/<时间与UUID>/` 目录：

- `run-start.json`：启动信息、采集规模、并发数和源码校验值。
- `source/`：采集时使用的源码快照。子进程直接执行快照中的采集工具。
- `launches.ndjson`：2,000次启动与退出记录。
- `process-0001.json`～`process-2000.json`：每个进程的10段计数、段内合法/非法手数、手号范围、明细位置及SHA-256。
- 同编号 `.pairs.bin`：每进程100,000手的逐手两牌，共200,000字节；全实验400,000,000字节，约400 MB。每手2字节，牌编码为 `suit*13+rank`；非法牌堆用255、255占位。
- `manifest.json`：完成状态、源文件校验值、全部启动记录及计数文件校验值。失败保留记录，不自动重试，不将不完整数据当作完整实验。
- `derived/segment-01.json`～`segment-10.json`：按段纵向组织的2,000个进程计数，可重新生成。
- `derived/verification.json`：报告与原始计数、所有累计数量、旧文件未变的核对结果。

所有段共用一个进程的原始两牌文件，但通过段编号、偏移量和独立校验值明确分开。无需为改变HTML效果重新采样。

## 运行命令

在本验证目录下执行。采集命令会产生一套全新数据：

```powershell
node src/startup-run.ts
```

只复算、重建新报告，不重新采样：

```powershell
node src/startup-report.ts results/startup-segments/<运行目录>
node src/startup-audit.ts results/startup-segments/<运行目录>
```

生成报告前，校验全部源码和数据文件，从2亿手两牌明细逐手复算每个进程每一段的169类计数，再生成十个互不混入记录的视图。
