#### 1. 先从最基础的问题开始

先让旁听者理解：

* MySQL 保存长期可靠的业务数据。
* Redis 保存访问更快的数据副本或临时状态。
* 缓存模式就是规定：**应用、Redis、MySQL 三者在读写时按什么顺序协作。**
* 四种模式的区别主要看：谁管理缓存、先写哪里、是否等待数据库。

#### 2. 用一张全景图认识四种模式

先只给出最容易记住的一句话：

* **Cache Aside：**业务代码自己管理缓存。
* **Read Through：**缓存组件自动处理读取和回源。
* **Write Through：**缓存和数据库同步写入。
* **Write Behind：**先写缓存，数据库以后再写。

这一部分只建立基本印象，不提前讲复杂的一致性问题。

#### 3. 再说明四种模式的分类

* Cache Aside 和 Read Through 重点讨论：**数据怎么读。**
* Write Through 和 Write Behind 重点讨论：**数据怎么写。**
* 它们不是四个连续等级，而是不同的读写协作方式。
* 一个系统可以组合使用读模式和写模式。
