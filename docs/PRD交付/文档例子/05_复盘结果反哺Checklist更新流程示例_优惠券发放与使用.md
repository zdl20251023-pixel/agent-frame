# 复盘结果反哺 Checklist 更新流程（轻量版）示例：优惠券发放与使用

## 1. 更新判断

仅当评审问题属于高频问题、关键问题，或影响研发评估、开工、验收时，才反哺 Checklist；一次性细节问题先观察，不直接加入。

| 情况 | 是否建议反哺 |
|---|---|
| 同类问题反复出现 | 是 |
| 问题影响研发评估 | 是 |
| 问题影响研发开工 | 是 |
| 问题影响验收判断 | 是 |
| 问题导致 PRD 被打回 | 是 |
| 一次性细节问题 | 否，先观察 |
| 只影响局部文案或展示 | 否，先观察 |

## 2. 更新记录

| 来源问题 | 对应 PRD 章节 | 原检查项 | 是否反哺 Checklist | 更新方式 | 更新后检查问题 |
|---|---|---|---|---|---|
| 订单取消后优惠券是否退回未明确 | 待确认点 / 关键规则 | 待确认点 | 是 | 调整 | 不明确的问题是否写清影响范围、默认处理、负责人和确认节点；其中影响开工、验收或数据状态的问题，是否已标出必须确认节点？ |
| 支付成功后优惠券状态更新失败的补偿处理未说明 | 异常处理 / 关键规则 | 异常处理 | 是 | 调整 | 已知主要异常是否写清发生位置、处理方式、用户 / 系统表现；其中影响状态一致性或重复操作风险的异常，是否已说明兜底处理方式？ |
| 后台修改优惠券活动配置后，是否影响已领取优惠券未明确 | 涉及范围 / 待确认点 | 涉及范围 | 观察 | 不更新 | 暂不更新，先观察后续配置类需求是否反复出现类似问题。 |
| 用户领取失败时需要展示哪些失败原因未明确 | 异常处理 / 验收标准 | 验收标准 | 否 | 不更新 | 不更新，属于本次需求的一次性提示文案和验收细节补充。 |
