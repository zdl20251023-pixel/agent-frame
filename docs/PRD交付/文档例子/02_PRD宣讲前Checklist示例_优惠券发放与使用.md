# 宣讲前 Checklist 示例：优惠券发放与使用


| 检查项    | 宣讲前确认问题                                              | 判断  | 需要补充的问题                                                                                                                                 |
| ------ | ---------------------------------------------------- | --- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 需求目标   | 是否能让研发理解为什么做、解决谁的问题、本期不做什么？                          | 是   | 已说明目标用户是运营人员和下单用户；当前问题是缺少优惠券配置、领取和下单抵扣能力；本期不包含复杂人群定向发券、多平台联合优惠和优惠券叠加使用。                                                                 |
| 本期范围边界 | 是否明确本期做什么、不做什么、主要影响范围？                               | 是   | 已明确本期支持运营创建优惠券活动、用户领取优惠券、下单选择优惠券并完成抵扣；不包含复杂人群定向发券、多平台联合优惠、优惠券叠加使用和复杂营销活动组合；主要影响管理后台、用户端活动页、用户端下单页、优惠券服务端逻辑、订单金额计算和优惠券状态流转。              |
| 主流程    | 是否能让研发看懂整体流程、模块流程和关键节点？即使没有界面效果图，是否也能通过文档理解功能主要实现方式？ | 是   | 已说明运营创建活动、用户领取、下单使用、系统校验、支付后状态更新的整体流程；也拆分了优惠券配置、优惠券领取、优惠券下单使用和优惠券状态更新模块。即使暂时没有界面效果图，也能通过当前文档理解运营在哪里配置、用户在哪里领取、下单时怎么使用、系统如何校验、支付后状态如何变化。 |
| 涉及范围   | 是否能让研发判断会改哪些端、后台、配置、服务端、系统或已有数据？                     | 是   | 已确认涉及用户端、管理后台、配置项 / 配置表、服务端逻辑、已有数据 / 历史流程；不涉及第三方系统。                                                                                     |
| 关键规则   | 是否能让研发理解核心规则、细分判断、特殊情况和处理结果？                         | 是   | 已说明优惠券领取规则和使用规则，包括活动有效期、领取次数、库存、使用门槛、适用商品、有效期校验和支付后状态变化。                                                                                |
| 验收标准   | 是否说明主流程哪些场景算通过、哪些情况不通过？                              | 是   | 已覆盖主流程验收：运营创建优惠券活动、用户领取优惠券、用户下单使用优惠券、支付成功后优惠券状态更新；也说明了主流程中不能算通过的情况，例如符合条件无法领取、下单页无法展示可用券、订单金额未正确抵扣、支付成功后状态未更新、已使用券仍可再次抵扣。               |
| 待确认点   | 不明确的问题是否写清影响范围、默认处理、负责人和确认节点？                        | 是   | 已列出订单取消后优惠券是否退回、订单退款后优惠券是否退回、后台修改配置后是否影响已领取优惠券等待确认点，并标明影响范围、默认建议、负责人和确认节点。                                                              |
| 异常处理   | 已知主要异常是否写清发生位置、处理方式和用户 / 系统表现？                       | 是   | 已说明重复领取、库存发完、订单金额未达到门槛、优惠券已过期等主要异常处理方式。其他复杂异常可由研发和测试在评审或开发过程中记录后讨论，不要求产品在 PRD 阶段全部写全。                                                   |
| AI 检查  | 是否已通过工具按以上检查项完成自动检查，并确认无明显缺口？                        | 通过  | 已完成 AI 自动检查，当前未发现影响宣讲、研发评估和主流程验收的明显缺口。                                                                                                  |
