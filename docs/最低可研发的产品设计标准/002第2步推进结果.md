# PRD 可评估最低标准模板（极简框架版）

## 1. 需求目标

说明为什么做这个需求，主要解决什么问题。

## 2. 主流程

说明用户或业务操作的大致流程，让研发能看懂功能怎么走。

## 3. 涉及范围

说明这个需求涉及哪些部分，比如用户端、管理后台、配置表、服务端逻辑、其他系统等。

## 4. 关键规则

说明会影响研发实现和验收的核心业务规则。

## 5. 验收标准

说明做到什么程度算完成，方便研发和测试判断结果是否符合预期。

## 6. 待确认点

把暂时不明确、需要产品或研发后续确认的问题先标出来，避免研发靠猜。

## 7. 异常处理

不要求一次性覆盖所有异常分支。

产品先说明已知的主要异常；开发过程中发现遗漏的异常，由研发提出后和产品确认最终效果。
