# PRD 示例：优惠券发放与使用

## 1. 需求目标

- 目标用户 / 使用对象：

运营人员、下单用户。

- 当前问题：

目前运营无法灵活创建优惠券活动，用户下单时也没有统一的优惠券领取和抵扣能力。

- 目标结果：

运营可以在管理后台创建优惠券活动，用户可以领取优惠券，并在下单时使用优惠券完成订单抵扣。

- 本期不包含：

不包含复杂人群定向发券、不包含多平台联合优惠、不包含优惠券叠加使用。

---

## 2. 主流程

- 整体流程：

运营在管理后台创建优惠券活动 → 配置发放规则和使用规则 → 用户进入活动页领取优惠券 → 用户下单时选择可用优惠券 → 系统校验优惠券是否可用 → 抵扣订单金额 → 支付完成后更新优惠券状态。

- 模块流程：

  - 优惠券配置模块：

    运营进入管理后台 → 新建优惠券活动 → 填写优惠券名称、面额、有效期、发放数量、适用商品和使用门槛 → 保存配置 → 活动生效。

  - 用户领取模块：

    用户进入活动页 → 点击领取优惠券 → 系统判断用户是否符合领取条件 → 符合条件则领取成功 → 优惠券进入用户账户。

  - 下单使用模块：

    用户进入下单页 → 系统查询用户可用优惠券 → 用户选择优惠券 → 系统校验有效期、使用门槛和适用商品 → 抵扣订单金额 → 用户支付。

  - 优惠券状态模块：

    优惠券创建后为未领取 → 用户领取后变为未使用 → 下单支付成功后变为已使用 → 超过有效期后变为已过期。

- 关键节点：

  - 领取时需要判断用户是否已经领取过、活动是否有效、库存是否充足；
  - 下单时需要判断优惠券是否在有效期内、订单金额是否满足门槛、商品是否适用；
  - 支付成功后需要更新优惠券状态，避免重复使用；
  - 订单取消或退款时，需要确认优惠券是否退回；
  - 管理后台配置变更后，需要确认是否影响已领取优惠券。

---

## 3. 涉及范围

主要影响对象：

用户、优惠券、优惠券活动、订单、商品、用户账户。

| 范围 | 是否涉及 | 改动类型 | 简单说明 |
|---|---|---|---|
| 用户端 | 是 | 修改 | 活动页支持用户领取优惠券，下单页展示可用优惠券并支持选择抵扣 |
| 管理后台 | 是 | 新增 | 新增优惠券活动配置入口，支持配置面额、有效期、发放数量、适用商品和使用门槛 |
| 配置项 / 配置表 | 是 | 新增 | 需要保存优惠券活动规则、发放规则、使用规则和生效时间 |
| 服务端逻辑 | 是 | 新增 | 需要处理优惠券领取、使用校验、订单抵扣和状态更新 |
| 其他系统 / 第三方 | 否 | 不涉及 | 本期不涉及第三方系统 |
| 已有数据 / 历史流程 | 是 | 修改 | 需要确认订单取消或退款后，优惠券是否退回以及状态如何处理 |

改动类型说明：

- 新增：原来没有，需要新做；
- 修改：原来已有，这次要调整；
- 复用：沿用已有能力，只是接入或使用；
- 待确认：不确定是否影响，需要研发评估；
- 不涉及：本次不影响这个范围。

---

## 4. 关键规则

### 规则：优惠券领取规则

- 规则对象：
  - 业务范围：优惠券活动流程
  - 功能模块：用户领取优惠券
  - 具体对象：用户、优惠券、优惠券活动

- 主规则：

用户只能在活动有效期内领取符合条件的优惠券。

- 子规则：
  - 领取时间：当前时间必须在优惠券活动有效期内；
  - 领取次数：同一用户同一活动下只能领取一次。

- 特殊情况：

如果优惠券已发放完，用户不能继续领取。

- 处理结果：

满足领取条件时，优惠券进入用户账户；不满足条件时，领取失败，并提示失败原因。

---

### 规则：优惠券使用规则

- 规则对象：
  - 业务范围：下单支付流程
  - 功能模块：优惠券使用
  - 具体对象：用户、优惠券、订单

- 主规则：

用户下单时，只能使用满足条件的优惠券抵扣订单金额。

- 子规则：
  - 有效期：优惠券必须在有效期内；
  - 使用门槛：订单金额必须达到优惠券使用门槛。

- 特殊情况：

如果订单取消或退款，需要确认优惠券是否退回。

- 处理结果：

满足使用条件时，优惠券可用于抵扣订单金额；不满足条件时，优惠券不可用，并提示不可用原因。

---

## 5. 验收标准

### 5.1 验收范围

- 用户端：用户可以在活动页领取优惠券，并在下单页查看和选择可用优惠券。
- 管理后台：运营可以创建优惠券活动，并配置面额、有效期、发放数量、适用商品和使用门槛。
- 配置项 / 配置表：优惠券活动规则、发放规则、使用规则保存后能够按配置生效。
- 服务端逻辑：系统能完成优惠券领取校验、使用校验、订单抵扣和优惠券状态更新。
- 数据 / 状态：优惠券状态能按领取、使用、过期等节点正确变化。
- 其他系统 / 第三方：不涉及。

### 5.2 验收场景

| 场景 | 操作 / 条件 | 预期结果 |
|---|---|---|
| 用户领取优惠券 | 用户在活动有效期内点击领取，且未领取过该优惠券 | 领取成功，优惠券进入用户账户 |
| 重复领取优惠券 | 同一用户再次领取同一活动优惠券 | 领取失败，并提示已领取 |
| 下单使用优惠券 | 用户下单时选择有效期内、满足门槛的优惠券 | 优惠券可用，订单金额正确抵扣 |
| 不满足门槛使用 | 用户订单金额未达到优惠券使用门槛 | 优惠券不可用，并提示不满足使用条件 |
| 支付成功后状态更新 | 用户使用优惠券完成支付 | 优惠券状态变为已使用，不能再次使用 |

### 5.3 不通过情况

- 用户不符合领取条件，但仍然可以领取优惠券；
- 用户订单不满足使用门槛，但优惠券仍然可以抵扣；
- 支付成功后，优惠券状态没有变为已使用；
- 同一张优惠券可以被重复使用；
- 管理后台配置保存后，用户端没有按配置生效。

## 6. 待确认点

| 待确认问题 | 影响范围 | 当前建议 / 默认处理 | 负责人 | 确认节点 |
|---|---|---|---|---|
| 订单取消后优惠券是否退回？ | 优惠券状态、订单流程、用户账户 | 默认建议退回未过期优惠券；已过期优惠券不退回 | 产品负责人 | 开发前 |
| 订单退款后优惠券是否退回？ | 退款流程、优惠券状态、用户可用券列表 | 默认建议全额退款退回优惠券，部分退款不退回 | 产品负责人 / 财务确认人 | 开发前 |
| 后台修改优惠券活动配置后，是否影响已领取优惠券？ | 管理后台配置、已领取优惠券、用户端展示 | 默认建议只影响后续领取，不影响已领取优惠券 | 产品负责人 | 联调前 |
| 优惠券库存发完后，活动页是否继续展示？ | 用户端活动页、优惠券领取流程 | 默认建议继续展示活动，但按钮置灰并提示“已领完” | 产品负责人 | 开发中 |
| 用户领取失败时，需要展示哪些失败原因？ | 用户端提示、领取校验逻辑 | 默认展示：已领取、活动已结束、优惠券已发完、不符合领取条件 | 产品 / 研发确认 | 验收前 |

确认节点可选：开发前 / 开发中 / 联调前 / 验收前。

## 7. 异常处理

### 7.1 已知异常

| 异常发生位置 | 异常情况 | 处理方式 | 用户 / 系统表现 |
|---|---|---|---|
| 用户领取优惠券时 | 用户重复领取同一活动优惠券 | 系统拦截领取请求，不新增优惠券记录 | 用户看到“已领取，请勿重复领取”提示 |
| 用户领取优惠券时 | 优惠券库存已发完 | 系统禁止继续领取 | 用户看到“优惠券已领完”提示，领取按钮置灰 |
| 用户下单使用优惠券时 | 订单金额未达到使用门槛 | 系统判断优惠券不可用，不允许抵扣 | 下单页展示该优惠券不可用，并提示“不满足使用门槛” |
| 用户下单使用优惠券时 | 优惠券已过期 | 系统判断优惠券不可用，不允许抵扣 | 下单页不展示该券，或展示为已过期状态 |
| 支付完成后 | 支付成功但优惠券状态未更新 | 系统需要补偿更新优惠券状态，避免重复使用 | 用户侧订单金额保持已抵扣结果，后台状态需修正为已使用 |
| 管理后台配置时 | 运营配置的有效期结束时间早于开始时间 | 系统不允许保存配置 | 后台提示“结束时间不能早于开始时间” |

### 7.2 未覆盖异常处理

| 未覆盖异常 | 发现阶段 | 影响范围 | 确认人 | 最终处理方式 |
|---|---|---|---|---|
| 用户领取成功后，活动配置被后台关闭，用户账户里的券是否还能使用 | 开发中 | 优惠券状态、用户账户、下单使用 | 产品负责人 | 待确认 |
| 用户支付过程中优惠券刚好过期，是否允许继续支付 | 联调中 | 支付流程、优惠券使用校验、订单金额 | 产品负责人 / 研发负责人 | 待确认 |
| 订单部分退款后，优惠券是否退回 | 验收中 | 退款流程、优惠券状态、用户可用券列表 | 产品负责人 / 财务确认人 | 待确认 |
