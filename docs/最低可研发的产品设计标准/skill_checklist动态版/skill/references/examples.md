# 检查示例（examples）

提供三类结论的样例，帮助 Skill 校准判断尺度。示例为节选，实际输出请用完整模板。

---

## 示例 1：可以宣讲

**输入特征**：以「优惠券发放与使用」PRD 为例，需求目标含目标用户/当前问题/目标结果/本期不包含；主流程含整体流程、4 个模块流程、关键节点；涉及范围表 6 行齐全且标注改动类型；关键规则按完整判断链书写；验收标准含范围、5 个场景、不通过情况；待确认点 5 项含影响范围/负责人/确认节点；异常处理含已知异常表与未覆盖异常机制。

**报告节选**：

```markdown
## 一、整体结论
- 结论：可以宣讲
- 一句话说明：七项检查均通过，范围、规则、验收闭环一致，未发现阻塞性矛盾。
- 使用的 Checklist 来源：用户提供

## 二、分项检查表（节选）
| 检查项 | 判断结果 | 依据说明 | 发现的问题 | 风险等级 | 补充建议 |
|---|---|---|---|---|---|
| 需求目标 | 通过 | 目标用户/问题/结果/边界齐全且可验证 | 无 | - | 无 |
| 验收标准 | 通过 | 含范围+5 场景+不通过情况，与目标对应 | 无 | - | 无 |
```

## 示例 2：可宣讲但需补充

**输入特征**：核心章节齐全且研发可评估，但异常处理只覆盖主流程，未说明「支付中优惠券刚好过期」的处理；待确认点缺确认节点。

**报告节选**：

```markdown
## 一、整体结论
- 结论：可宣讲但需补充
- 一句话说明：目标/范围/流程/规则/验收可支撑评估，异常处理与待确认点有 P1 缺口，可宣讲前补齐或宣讲中确认。
- 使用的 Checklist 来源：用户提供

## 二、分项检查表（节选）
| 检查项 | 判断结果 | 依据说明 | 发现的问题 | 风险等级 | 补充建议 |
|---|---|---|---|---|---|
| 异常处理 | 需补充 | 已知异常表有，但漏关键失败节点 | 未覆盖「支付中优惠券过期」 | P1 | 补充该场景处理方式与用户表现 |
| 待确认点 | 需补充 | 问题与影响范围有，缺确认节点 | 退款是否退券未标确认节点 | P1 | 补充负责人与确认节点 |

## 四、宣讲前补充清单
### P1 建议补齐（影响评估）
1. 异常处理补充「支付过程中优惠券过期」场景。
2. 待确认点补齐确认节点。

## 五、可复制补充建议
> 以下为建议草案，需产品负责人确认后再写入 PRD。
- 异常处理新增一行：发生位置「支付提交时」/ 异常「优惠券在支付中过期」/ 处理方式「待产品确认是否允许继续支付」/ 用户表现「待确认」。
```

## 示例 3：暂不建议宣讲

**输入特征**：需求目标只写「优化下单体验」，无目标用户与可验证结果；无主流程；涉及范围表为空；关键规则只有结果无判断条件；验收标准只写「功能正常」。

**报告节选**：

```markdown
## 一、整体结论
- 结论：暂不建议宣讲
- 一句话说明：目标空泛、缺主流程、范围表为空、规则与验收不可评估，研发无法据此评估，存在多个 P0。
- 使用的 Checklist 来源：用户提供

## 二、分项检查表（节选）
| 检查项 | 判断结果 | 依据说明 | 发现的问题 | 风险等级 | 补充建议 |
|---|---|---|---|---|---|
| 需求目标 | 不通过 | 仅「优化体验」，无用户/可验证结果 | 目标无法验证 | P0 | 补充目标用户、当前问题、可验证目标结果 |
| 主流程 | 不通过 | 未提供任何流程 | 缺整体/模块/节点 | P0 | 补充整体流程与关键节点 |
| 涉及范围 | 不通过 | 范围表为空 | 无法判断影响面 | P0 | 按 6 个范围逐行填写 |
| 验收标准 | 不通过 | 仅「功能正常」 | 无场景/预期结果 | P0 | 补充验收场景与不通过情况 |

## 四、宣讲前补充清单
### P0 必须补齐（阻塞宣讲）
1. 需求目标：补目标用户、当前问题、可验证目标结果、本期不包含。
2. 主流程：补整体流程、模块流程、关键节点。
3. 涉及范围：补范围表与改动类型。
4. 验收标准：补验收范围、场景、不通过情况。
```

## 示例 4：无法判断

**输入特征**：用户仅提供 Checklist，或 PRD 为图片型 PDF / 扫描件无法读取文本。

**报告节选**：

```markdown
## 一、整体结论
- 结论：无法判断
- 一句话说明：未获得可读取的 PRD 文本（仅扫描件），无法完成有效检查。请提供文本或 Markdown 版 PRD。
```
