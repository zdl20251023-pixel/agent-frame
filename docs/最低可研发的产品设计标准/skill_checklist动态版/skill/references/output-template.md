# 输出模板（output-template）

Skill 必须按本模板输出报告，顺序与字段不可省略。输出不能只给「是 / 否」，必须服务宣讲前决策。

---

## 模板

```markdown
# PRD 宣讲前自查报告

## 一、整体结论

- 结论：可以宣讲 / 可宣讲但需补充 / 暂不建议宣讲 / 无法判断
- 一句话说明：（为什么是这个结论，关键阻塞或缺口是什么）
- 使用的 Checklist 来源：用户提供 / 默认规则
- 检查轮次：第 N 轮（二次检查时填写）

## 二、分项检查表

| 检查项 | 判断结果 | 依据说明 | 发现的问题 | 风险等级 | 补充建议 |
|---|---|---|---|---|---|
| 需求目标 | 通过/需补充/不通过/不涉及/待确认 |  |  | P0/P1/P2/- |  |
| 主流程 |  |  |  |  |  |
| 涉及范围 |  |  |  |  |  |
| 关键规则 |  |  |  |  |  |
| 验收标准 |  |  |  |  |  |
| 待确认点 |  |  |  |  |  |
| 异常处理 |  |  |  |  |  |
| AI 检查 | 通过/需补充/未检查 |  |  | - |  |

> 检查项以输入的 Checklist 为准；上表为默认 7 项 + AI 检查项示例。

## 三、一致性 / 反证检查结果

- 列出发现的矛盾、遗漏或冲突；
- 无矛盾时写「未发现明显矛盾」。

## 四、宣讲前补充清单

### P0 必须补齐（阻塞宣讲）
1.

### P1 建议补齐（影响评估）
1.

### P2 可优化（表达优化）
1.

## 五、可复制补充建议

> 以下为建议草案，需产品负责人确认后再写入 PRD。

- 针对【某检查项】的缺失，给出可直接粘贴进 PRD 的草案文本。
```

---

## 填写要求

- **整体结论**：当存在任一 P0 项时，结论不得为「可以宣讲」；输入不足以完成检查时使用「无法判断」并说明缺什么。
- **分项检查表**：每项都要有判断结果、依据说明、发现的问题、风险等级、补充建议；判断为「通过」时风险等级填「-」，补充建议可填「无」。
- **风险等级**：仅 P0 / P1 / P2，定义见 review-rubric.md。
- **补充清单**：按 P0 → P1 → P2 优先级排列；无对应项时写「无」。
- **可复制补充建议**：必须带「以下为建议草案，需产品负责人确认后再写入 PRD。」声明，且不得编造业务规则。
- **二次检查**：在「整体结论」中对比上一轮，标明已修复项与新出现的阻塞项。
