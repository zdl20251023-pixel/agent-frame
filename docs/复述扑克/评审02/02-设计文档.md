# 三、系统交互

## 3.1 是否有新增服务器

无。

本需求不新增独立服务器，复用当前已有链路，在现有系统上新增复式扑克 PvE 排名赛相关能力。

| 模块       | 说明                                |
| -------- | --------------------------------- |
| `Admin`  | 管理后台，配置手牌、牌局包、活动                  |
| `client` | 用户端，查看活动、参赛、打牌、查榜                 |
| `web`    | 无状态 Web 层，负责活动业务编排、进度查询、计分落库、榜单查询 |
| `Game`   | 有状态游戏服务，负责具体 table 运行过程           |
| `MySQL`  | 比赛事实源，保存活动、参赛、手牌、计分、榜单数据          |
| `Redis`  | 保存本手临时结果、排行榜缓存、活动结算锁              |
| `Worker` | 活动截止后的最终榜结算任务                     |

说明：

```text
PlayerProxy、TableSession、TableMachine 属于 Game 内部子功能模块。
本设计文档主时序图不展开这些内部模块。
AI 只是一局牌内部轮到 AI 行动时的能力，不放入排名赛系统主流程。
```

## 3.2 是否有 CS 交互，SS 交互

有。

| 类型            | 说明                               |
| ------------- | -------------------------------- |
| CS 交互         | `client / Admin -> web`          |
| web 与 Game 交互 | `web -> Game`，用于创建牌桌、牌桌操作、获取牌局结果 |
| DB 交互         | `web -> MySQL`、`web -> Redis`    |
| Worker 交互     | `Worker -> MySQL / Redis`        |

### 3.2.1 系统交互总览：以 N=2 为例

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant Game
    participant MySQL
    participant Redis
    participant Worker

    client->>web: get_activity_list
    web->>MySQL: 查询已发布活动和用户参赛状态
    MySQL-->>web: 返回活动列表
    web-->>client: 返回活动列表

    client->>web: join_activity(activity_id)
    web->>MySQL: 创建或查询 user_entry
    web->>MySQL: 首次参赛时分配 2 手牌，写入 user_hand
    MySQL-->>web: 返回基础参赛信息
    web-->>client: 返回 entry_id、activity_id、join_status

    client->>web: resume_activity(activity_id)
    web->>MySQL: 查询 activity、user_entry、user_hand、leaderboard_result
    MySQL-->>web: 返回当前进度：第 1 手未完成
    web-->>client: 返回当前应开始第 1 手

    client->>web: start_hand(user_hand_id_1)
    web->>MySQL: 校验第 1 手是否可开始
    web->>MySQL: 查询第 1 手对应 drill_id
    web->>MySQL: 更新第 1 手 status=playing
    web-->>client: 返回 create_table 所需参数

    client->>web: create_table，携带第 1 手参数
    web->>Game: 转发 create_table 请求
    Game-->>web: 返回 table_id_1
    web-->>client: 返回 table_id_1

    client->>web: 正常进行第 1 手牌桌操作
    web->>Game: 转发牌桌操作
    Game-->>web: 返回牌桌状态
    web-->>client: 返回牌桌状态

    Game->>Redis: 第 1 手牌局结束，缓存本手比赛结果

    client->>web: submit_hand(user_hand_id_1, table_id_1)
    web->>Redis: 获取第 1 手牌局结果
    Redis-->>web: 返回第 1 手结果
    web->>MySQL: 写入 hand_score，更新第 1 手 completed
    web->>MySQL: 更新 entry.completed_hand_count=1
    web->>Redis: 删除第 1 手临时结果
    web-->>client: 返回第 1 手基础结果

    client->>web: resume_activity(activity_id)
    web->>MySQL: 查询当前活动进度
    MySQL-->>web: 返回当前进度：已完成 1/2，第 2 手未完成
    web-->>client: 返回当前应开始第 2 手

    client->>web: start_hand(user_hand_id_2)
    web->>MySQL: 校验第 2 手是否可开始
    web->>MySQL: 查询第 2 手对应 drill_id
    web->>MySQL: 更新第 2 手 status=playing
    web-->>client: 返回 create_table 所需参数

    client->>web: create_table，携带第 2 手参数
    web->>Game: 转发 create_table 请求
    Game-->>web: 返回 table_id_2
    web-->>client: 返回 table_id_2

    client->>web: 正常进行第 2 手牌桌操作
    web->>Game: 转发牌桌操作
    Game-->>web: 返回牌桌状态
    web-->>client: 返回牌桌状态

    Game->>Redis: 第 2 手牌局结束，缓存本手比赛结果

    client->>web: submit_hand(user_hand_id_2, table_id_2)
    web->>Redis: 获取第 2 手牌局结果
    Redis-->>web: 返回第 2 手结果
    web->>MySQL: 写入 hand_score，更新第 2 手 completed
    web->>MySQL: 更新 entry.completed_hand_count=2
    web->>MySQL: 完成 2/2，写入 leaderboard_result
    web->>Redis: 删除第 2 手临时结果，失效当前榜缓存
    web-->>client: 返回第 2 手基础结果

    client->>web: resume_activity(activity_id)
    web->>MySQL: 查询当前活动进度
    MySQL-->>web: 返回当前进度：已完成 2/2，已进入当前榜
    web-->>client: 返回当前榜入口和用户完成状态

    client->>web: get_current_leaderboard(activity_id)
    web->>Redis: 查询当前榜缓存
    web->>MySQL: Redis miss 时回源查询 leaderboard_result
    web-->>client: 返回当前榜数据

    Worker->>MySQL: 活动时间过期后，扫描待结算活动
    Worker->>Redis: 获取活动结算锁
    Worker->>MySQL: 查询 leaderboard_result
    Worker->>MySQL: 按 total_score DESC, complete_time ASC 生成 rank_no
    Worker->>MySQL: 更新 is_final=1、finalized_at、activity.status=finalized
    Worker->>Redis: 删除或刷新榜单缓存
```

关键说明：

```text
本例中 N=2，用户必须完成 2 手牌才算完赛。
join_activity 只返回基础参赛信息。
resume_activity 是统一恢复活动进度的接口。
start_hand 不创建牌桌，只返回 create_table 所需参数。
client 根据 start_hand 返回参数走已有 create_table 流程。
submit_hand 每次只返回本手基础结果。
每次 submit_hand 后，client 都再次调用 resume_activity 获取最新进度。
第 1 手 submit_hand 后，resume_activity 判断未完成 2/2，继续第 2 手。
第 2 手 submit_hand 后，resume_activity 判断已完成 2/2，进入当前榜。
活动时间过期后，由 Worker 触发最终榜结算。
```

### 3.2.2 后台角度接口时序图：配置活动

```mermaid
sequenceDiagram
    autonumber
    participant Admin
    participant web
    participant MySQL

    Admin->>web: create_hand，提交 drill_id、title
    web->>MySQL: 写入 duplicate_match_hand
    MySQL-->>web: 返回 hand_id
    web-->>Admin: 返回手牌创建结果

    Admin->>web: create_hand_pack
    web->>MySQL: 写入 duplicate_match_hand_pack
    MySQL-->>web: 返回 hand_pack_id
    web-->>Admin: 返回牌局包创建结果

    Admin->>web: add_hand_pack_item
    web->>MySQL: 写入 duplicate_match_hand_pack_item
    MySQL-->>web: 返回配置结果
    web-->>Admin: 返回配置结果

    Admin->>web: create_activity
    web->>MySQL: 校验 hand_pack_id、play_hand_count、start_time、end_time
    web->>MySQL: 写入 duplicate_match_activity，status=draft
    MySQL-->>web: 返回 activity_id
    web-->>Admin: 返回活动创建结果

    Admin->>web: publish_activity
    web->>MySQL: 校验活动配置完整性
    web->>MySQL: 更新 activity.status=published
    MySQL-->>web: 返回发布结果
    web-->>Admin: 返回发布成功
```

关键说明：

```text
后台配置流程只经过 web 和 MySQL，不需要 Game 参与。
手牌通过 drill_id 关联已有 drill 玩法，不复制 drill 内部数据。
play_hand_count 来自后台配置，不能写死。
```

### 3.2.4 用户角度接口时序图：参加活动

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant MySQL

    client->>web: join_activity(activity_id)
    web->>MySQL: 查询 activity 是否可参加
    web->>MySQL: 查询是否已有 user_entry

    alt 已参赛
        MySQL-->>web: 返回已有 user_entry
        web-->>client: 返回基础参赛信息
    else 未参赛
        web->>MySQL: 开启事务
        web->>MySQL: 写入 duplicate_match_user_entry
        web->>MySQL: 根据 play_hand_count 分配 N 手牌
        web->>MySQL: 批量写入 duplicate_match_user_hand
        web->>MySQL: 提交事务
        web-->>client: 返回基础参赛信息
    end
```

返回信息：

```text
entry_id
activity_id
join_status
```

关键说明：

```text
join_activity 需要幂等。
join_activity 不返回完整当前进度。
join_activity 成功后，client 继续调用 resume_activity 获取当前进度。
```

### 3.2.5 用户角度接口时序图：恢复活动进度

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant MySQL

    client->>web: resume_activity(activity_id)
    web->>MySQL: 查询 activity
    web->>MySQL: 查询 user_entry
    web->>MySQL: 查询 user_hand
    web->>MySQL: 查询 hand_score
    web->>MySQL: 查询 leaderboard_result
    MySQL-->>web: 返回活动进度数据
    web-->>client: 返回当前进度和下一步动作
```

返回状态示例：

| 状态           | 前端动作       |
| ------------ | ---------- |
| `not_joined` | 展示开始挑战     |
| `joined`     | 展示当前应开始的手牌 |
| `playing`    | 展示继续当前手    |
| `completed`  | 展示当前榜入口    |
| `finalized`  | 展示最终榜入口    |
| `expired`    | 展示已截止      |

关键说明：

```text
resume_activity 是统一恢复活动进度的接口。
前端页面跳转优先以 resume_activity 返回结果为准。
```

### 3.2.9 用户角度接口时序图：提交每手结果

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant Redis
    participant MySQL

    client->>web: submit_hand(user_hand_id, table_id)
    web->>MySQL: 查询 user_hand 是否已完成
    alt 已完成
        MySQL-->>web: 返回已有 hand_score
        web-->>client: 返回本手基础结果
    else 未完成
        web->>Redis: 根据 user_hand_id / table_id 获取本手结果
        Redis-->>web: 返回本手结果
        web->>MySQL: 开启事务
        web->>MySQL: 写入 duplicate_match_hand_score
        web->>MySQL: 更新 user_hand.status=completed
        web->>MySQL: 更新 user_entry 完成手数和总分
        alt 已完成 N 手
            web->>MySQL: 写入 duplicate_match_leaderboard_result
        end
        web->>MySQL: 提交事务
        web->>Redis: 删除本手临时结果，失效当前榜缓存
        web-->>client: 返回本手基础结果
    end
```

返回信息：

```text
user_hand_id
score
win_loss_bb
completed_hand_count
```

关键说明：

```text
submit_hand 只返回本手基础结果。
submit_hand 不负责返回完整下一步页面状态。
submit_hand 后，client 继续调用 resume_activity 获取最新进度。
submit_hand 需要幂等。
```

### 3.2.10 用户角度接口时序图：查询当前榜

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant Redis
    participant MySQL

    client->>web: get_current_leaderboard(activity_id)
    web->>Redis: 查询当前榜分页缓存

    alt Redis 命中
        Redis-->>web: 返回缓存榜单
    else Redis 未命中
        web->>Redis: 获取短锁 / singleflight
        web->>MySQL: 查询 leaderboard_result 动态排序
        web->>Redis: 写入分页缓存
    end

    web-->>client: 返回当前榜
```

关键说明：

```text
当前榜只展示完成 N 手的用户。
排序：total_score DESC, complete_time ASC。
Redis miss 时回源 MySQL。
```

### 3.2.12 Worker 角度时序图：活动截止后最终榜结算

```mermaid
sequenceDiagram
    autonumber
    participant Worker
    participant Redis
    participant MySQL

    Worker->>MySQL: 扫描已截止且未 finalized 的活动
    Worker->>Redis: 获取 activity_id 结算锁

    alt 获取锁失败
        Worker-->>Worker: 跳过本次结算
    else 获取锁成功
        Worker->>MySQL: 查询完成 N 手的 leaderboard_result
        Worker->>MySQL: 按 total_score DESC, complete_time ASC 排序
        Worker->>MySQL: 写入 rank_no、is_final、finalized_at
        Worker->>MySQL: 更新 activity.status=finalized
        Worker->>Redis: 删除或刷新榜单缓存
        Worker->>Redis: 释放结算锁
    end
```

关键说明：

```text
Worker 通过 Redis 结算锁避免重复结算。
最终榜以 MySQL 写入结果为准。
Worker 重复执行需要幂等。
```
