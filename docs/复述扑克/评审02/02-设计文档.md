# 三、系统交互

## 3.1 是否有新增服务器

无。

本需求不新增独立服务器，复用当前已有链路，在现有系统上新增复式扑克 PvE 排名赛相关能力。

| 模块       | 说明                                          |
| -------- | ------------------------------------------- |
| `client` | 用户端 / 管理后台前端，负责活动查看、参赛、打牌、查榜，以及后台配置入口       |
| `Admin`  | 管理后台服务，负责手牌、牌局包、活动配置，直接操作 MySQL             |
| `web`    | 无状态 Web 层，负责用户活动业务编排、进度查询、计分落库、榜单查询         |
| `Game`   | 有状态游戏服务，负责具体 table / drill 对局运行             |
| `MySQL`  | 比赛事实源，保存活动、参赛、手牌分配、计分、榜单数据                  |
| `Redis`  | 保存本手临时结果、Redis Sorted Set 加速当前榜、排行榜缓存、活动结算锁 |
| `Worker` | 活动截止后的最终榜结算任务                               |

## 3.2 是否有 CS 交互，SS 交互

有。

| 类型            | 说明                                             |
| ------------- | ---------------------------------------------- |
| 管理后台交互        | `client -> Admin -> MySQL`                     |
| 用户端 CS 交互     | `client -> web`                                |
| web 与 Game 交互 | `web -> Game`，用于创建排名赛 drill 对局、转发牌桌操作、获取牌桌状态   |
| DB 交互         | `Admin / web / Game / Worker -> MySQL / Redis` |
| Worker 交互     | `Worker -> MySQL / Redis`                      |

时序图标记说明：

```text
->>  尖角实线：异步请求 / 异步返回
-->> 虚线：同步请求 / 同步返回
-)   圆角实线：快速跳过步骤，用于表示本图不展开的简化流程
```

交互规则：

```text
client -> Admin：HTTP 异步请求 / 异步返回
client -> web：HTTP 异步请求 / 异步返回
web -> Game：HTTP/RPC 异步请求 / 异步返回

Admin / web / Game / Worker -> MySQL：同步请求 / 同步返回
Admin / web / Game / Worker -> Redis：同步请求 / 同步返回
```

### 3.2.1 系统交互总览：以 N=2 为例

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant Admin
    participant web
    participant Game
    participant MySQL
    participant Redis
    participant Worker

    client->>Admin: 后台配置手牌、牌局包、活动
    Admin-->>MySQL: 写入 hand、hand_pack、activity
    MySQL-->>Admin: 返回写入结果
    Admin->>client: 返回后台配置结果

    client->>web: get_activity_list
    web-->>MySQL: 查询已发布活动和用户参赛状态
    MySQL-->>web: 返回活动列表和参赛状态
    web->>client: 返回活动列表

    client->>web: join_activity(activity_id)
    web-->>MySQL: 查询或创建 user_entry
    web-->>MySQL: 首次参赛时分配 2 手牌，写入 user_hand
    MySQL-->>web: 返回基础参赛信息
    web->>client: 返回基础参赛信息

    client->>web: resume_activity(activity_id)
    web-->>MySQL: 查询用户活动进度
    MySQL-->>web: 返回当前应开始的手牌
    web->>client: 返回当前应开始的手牌

    loop 每手牌，直到完成 N 手
        client->>web: start_hand(user_hand_id)
        web-->>MySQL: 校验进度，读取 hand.drill_info，更新 user_hand=playing
        MySQL-->>web: 返回 create_duplicate_match_drill 参数
        web->>client: 返回 create_duplicate_match_drill 参数

        client->>web: create_duplicate_match_drill
        web->>Game: 创建排名赛 drill 对局
        Game->>web: 返回 table_info
        web->>client: 返回 table_info

        client->>web: 进行牌桌操作
        web->>Game: 转发牌桌操作

        alt 牌局未结束
            Game->>web: 返回牌桌进行中状态
            web->>client: 返回牌桌进行中状态
        else 牌局结束
            Game-->>Redis: 缓存本手比赛结果
            Redis-->>Game: 返回缓存成功
            Game->>web: 返回牌桌结束状态
            web->>client: 返回牌桌结束状态
        end

        client->>web: submit_hand(user_hand_id, table_id)
        web-->>Redis: 获取本手比赛结果
        Redis-->>web: 返回本手比赛结果
        web-->>MySQL: 写入 hand_score，更新 user_hand / user_entry
        MySQL-->>web: 返回落库结果
        web-->>Redis: 删除本手临时结果
        Redis-->>web: 返回删除结果
        web->>client: 返回本手基础结果

        client->>web: resume_activity(activity_id)
        web-->>MySQL: 查询最新活动进度
        MySQL-->>web: 返回下一手或榜单入口
        web->>client: 返回下一手或榜单入口
    end

    web-->>MySQL: 完成 2/2 后写入 leaderboard_result
    MySQL-->>web: 返回入榜结果
    web-->>Redis: 写入当前榜 Sorted Set 或失效当前榜缓存
    Redis-->>web: 返回处理结果

    client->>web: get_current_leaderboard(activity_id)
    web-->>Redis: 查询当前榜 Sorted Set / 缓存

    alt Redis 命中
        Redis-->>web: 返回当前榜
    else Redis 未命中
        Redis-->>web: 返回 miss
        web-->>MySQL: 回源查询 leaderboard_result
        MySQL-->>web: 返回当前榜
        web-->>Redis: 重建当前榜 Sorted Set / 缓存
        Redis-->>web: 返回重建结果
    end

    web->>client: 返回当前榜

    Worker-->>MySQL: 活动截止后扫描待结算活动
    MySQL-->>Worker: 返回待结算活动
    Worker-->>Redis: 获取活动结算锁
    Redis-->>Worker: 返回锁结果
    Worker-->>MySQL: 生成 rank_no，冻结最终榜
    MySQL-->>Worker: 返回结算结果
    Worker-->>Redis: 删除或刷新榜单缓存
    Redis-->>Worker: 返回处理结果
```

关键说明：

```text
submit_hand 根据 user_hand_id + table_id 从 Redis 读取本手比赛结果，并落库到 MySQL。

完成 N 手后，web 写入 leaderboard_result，并同步更新 Redis Sorted Set 或失效当前榜缓存。

当前榜以 MySQL 的 leaderboard_result 为事实源，Redis Sorted Set 只用于加速查询。

活动截止后由 Worker 结算最终榜，最终榜以 MySQL 冻结后的 rank_no 为准。
```

### 3.2.11 Worker 角度时序图：活动截止后最终榜结算

```mermaid
sequenceDiagram
    autonumber
    participant Worker
    participant Redis
    participant MySQL

    Worker-->>MySQL: 扫描已截止且未 finalized 的活动
    MySQL-->>Worker: 返回待结算活动
    Worker-->>Redis: 获取 activity_id 结算锁
    Redis-->>Worker: 返回锁结果

    alt 获取锁失败
        Worker-)Worker: 跳过本次结算
    else 获取锁成功
        Worker-->>MySQL: 查询完成 N 手的 leaderboard_result
        MySQL-->>Worker: 返回待排名数据
        Worker-->>MySQL: 按 total_score DESC, complete_time ASC 写入 rank_no、is_final、finalized_at
        Worker-->>MySQL: 更新 activity.status=finalized
        MySQL-->>Worker: 返回结算结果
        Worker-->>Redis: 删除或刷新榜单缓存
        Redis-->>Worker: 返回处理结果
    end
```

关键说明：

```text
Worker 通过 Redis 结算锁避免重复结算。
最终榜以 MySQL 写入结果为准。
Worker 重复执行需要幂等。

最终榜结算是低频操作，7.15 阶段优先保证正确性和可追溯性。
Worker 结算时从 MySQL leaderboard_result 重新读取完成用户并排序生成 rank_no。
Redis 当前榜 Sorted Set 不作为最终榜事实源。
如后续单活动完赛人数达到十万级，再评估分批结算、临时表或离线排行榜方案。
```

### 3.2.12 异常与幂等处理时序图

本节用于补充主流程中容易被追问的异常、幂等、并发和缓存一致性问题。

主流程时序图只表达正常链路；异常与特殊情况单独展开，避免主流程过重。

---

#### 3.2.12.1 `submit_hand` 重复提交 / 幂等处理

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant Redis
    participant MySQL

    client->>web: submit_hand(user_hand_id, table_id)
    web-->>MySQL: 查询 user_hand / hand_score

    alt hand_score 已存在
        MySQL-->>web: 返回已有 hand_score
        web->>client: 返回已有本手结果
    else user_hand 已 completed
        MySQL-->>web: 返回 user_hand completed
        web-->>MySQL: 查询已有 hand_score
        MySQL-->>web: 返回已有 hand_score
        web->>client: 返回已有本手结果
    else 未完成，首次提交
        MySQL-->>web: 返回未完成
        web-->>Redis: 获取本手比赛结果
        Redis-->>web: 返回本手比赛结果

        web-->>MySQL: 开启事务
        web-->>MySQL: 写入 duplicate_match_hand_score
        web-->>MySQL: 更新 user_hand.status=completed
        web-->>MySQL: 更新 user_entry 完成手数和总分
        web-->>MySQL: 提交事务
        MySQL-->>web: 返回落库结果

        web-->>Redis: 删除本手临时结果
        Redis-->>web: 返回删除结果
        web->>client: 返回本手基础结果
    end

    client->>web: 网络重试 / 重复 submit_hand
    web-->>MySQL: 再次查询 user_hand / hand_score
    MySQL-->>web: 返回已有 hand_score
    web->>client: 返回已有本手结果
```

关键说明：

```text
submit_hand 必须先查 user_hand / hand_score。

如果 hand_score 已存在，直接返回已有结果。

duplicate_match_hand_score.uk_user_hand(user_hand_id) 作为数据库唯一约束兜底。

重复提交不能重复计分，不能重复推进 completed_hand_count。
```

#### 3.2.12.2 Redis 本手比赛结果缺失

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant Redis
    participant MySQL

    client->>web: submit_hand(user_hand_id, table_id)
    web-->>MySQL: 查询 user_hand / hand_score
    MySQL-->>web: 返回未完成

    web-->>Redis: 根据 user_hand_id + table_id 获取本手比赛结果

    alt Redis 存在本手结果
        Redis-->>web: 返回本手比赛结果
        web-->>MySQL: 写入 hand_score，更新 user_hand / user_entry
        MySQL-->>web: 返回落库结果
        web-->>Redis: 删除本手临时结果
        Redis-->>web: 返回删除结果
        web->>client: 返回本手基础结果
    else Redis 结果缺失
        Redis-->>web: 返回 miss
        web-)web: 记录日志和监控
        web->>client: 返回结果未就绪，请稍后重试
    end
```

关键说明：

```text
Redis 本手结果缺失时，submit_hand 不落库。

不更新 user_hand.status=completed。

不更新 user_entry.completed_hand_count。
```

#### 3.2.12.11 断线 / 刷新 / 服务重启后继续活动

场景：用户打牌过程中断线、刷新页面、换设备重新进入，或 web 服务重启后，用户重新进入活动页。

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant MySQL
    participant Redis

    client->>web: resume_activity(activity_id)
    web-->>MySQL: 查询 activity
    web-->>MySQL: 查询 user_entry
    web-->>MySQL: 查询 user_hand
    web-->>MySQL: 查询 hand_score
    web-->>MySQL: 查询 leaderboard_result
    MySQL-->>web: 返回活动进度数据

    alt 未参赛
        web->>client: 返回 not_joined，展示开始挑战
    else 已完成 N 手
        web->>client: 返回 completed / finalized，展示榜单入口
    else 当前手 status=pending
        web->>client: 返回当前应开始的 user_hand
    else 当前手 status=playing 且 hand_score 不存在
        web->>client: 返回当前 user_hand，提示从本手开头重新开始
    else 当前手 status=completed 或 hand_score 已存在
        web-->>MySQL: 查询下一手 user_hand
        MySQL-->>web: 返回下一手或榜单入口
        web->>client: 返回下一步动作
    end

    opt 前端继续当前手
        client->>web: start_hand(user_hand_id)
        web-->>MySQL: 校验进度，读取 hand.drill_info
        MySQL-->>web: 返回 create_duplicate_match_drill 参数
        web->>client: 返回 create_duplicate_match_drill 参数
    end

    opt 如果前一次牌局已结束但 client 未 submit_hand
        client->>web: submit_hand(user_hand_id, table_id)
        web-->>Redis: 获取本手比赛结果
        alt Redis 仍存在本手结果
            Redis-->>web: 返回本手比赛结果
            web-->>MySQL: 写入 hand_score，更新 user_hand / user_entry
            MySQL-->>web: 返回落库结果
            web->>client: 返回本手基础结果
        else Redis 结果不存在
            Redis-->>web: 返回 miss
            web->>client: 返回结果未就绪，请重新开始本手或稍后重试
        end
    end
```

关键说明：

```text
resume_activity 是断线 / 刷新 / 换设备后的统一恢复入口。

web 是无状态服务，web 重启不影响活动恢复；恢复数据以 MySQL 为准。

恢复的是活动进度，不恢复单手中途牌局状态。

如果 user_hand.status=playing，但 hand_score 不存在，表示当前手未正式完成，重新进入时从这一手开头重新打。

如果 hand_score 已存在，说明本手已经完成，resume_activity 返回下一手或榜单入口。

如果前一次牌局已经结束，但 client 断线导致没有 submit_hand，可以再次 submit_hand 尝试从 Redis 获取本手结果。

如果 Redis 本手结果已经过期或缺失，submit_hand 不推进进度，前端需要重新开始本手或稍后重试。

最终是否完成、是否入榜，只以 MySQL 中的 user_hand、hand_score、leaderboard_result 为准。
```
