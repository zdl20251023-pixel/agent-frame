# 三、系统交互

## 3.1 是否有新增服务器

无。

本需求不新增独立服务器，复用当前项目已有链路，在现有 `Game` 服务中新增 PvE 排名赛相关能力。

| 模块       | 说明                                 |
| -------- | ---------------------------------- |
| `Admin`  | 管理后台，配置手牌、牌局包、活动                   |
| `client` | 用户端，进入活动、参赛、打牌、查榜                  |
| `web`    | Web 接入层，负责转发请求                     |
| `Game`   | 游戏服务，承载活动、参赛、手牌分配、PvE 对局接入、计分、榜单逻辑 |
| `MySQL`  | 比赛事实源，保存活动、参赛、计分、榜单数据              |
| `Redis`  | 排行榜缓存、活动结算锁                        |
| `Worker` | 活动截止后的最终榜结算                        |
| `AI`     | 复用已有 AI / drill 对局能力               |

说明：

```text
PlayerProxy、TableSession、TableMachine 属于 Game 内部子功能模块。
本设计文档主时序图不展开这些内部模块。
```

## 3.2 是否有CS交互，ss交互

有。

| 类型    | 说明                                     |
| ----- | -------------------------------------- |
| CS 交互 | `client / Admin -> web -> Game`        |
| SS 交互 | `Game -> AI`、`Worker -> MySQL / Redis` |
| DB 交互 | `Game -> MySQL`、`Game -> Redis`        |

---

### 3.2.1 系统交互总览

```mermaid
sequenceDiagram
    participant Admin
    participant client
    participant web
    participant Game
    participant MySQL
    participant Redis
    participant Worker
    participant AI

    Admin->>web: 配置手牌 / 牌局包 / 活动
    web->>Game: 转发后台配置请求
    Game->>MySQL: 写入 duplicate_match 配置数据

    client->>web: 参加活动 / 开始手牌 / 提交结果
    web->>Game: 转发用户请求
    Game->>MySQL: 读写参赛、手牌、计分、榜单数据
    Game->>AI: 进入已有 AI / drill 对局能力

    client->>web: 查询当前榜 / 最终榜
    web->>Game: 转发榜单查询
    Game->>Redis: 查询榜单缓存
    Game->>MySQL: Redis miss 时回源查询

    Worker->>Redis: 获取活动结算锁
    Worker->>MySQL: 结算最终榜并冻结排名
```

关键说明：

```text
MySQL 是事实源。
Redis 只做缓存和结算锁。
Game 内部如何驱动 TableSession / TableMachine 不在主时序图展开。
```

### 3.2.2 后台角度接口时序图：创建手牌

```mermaid
sequenceDiagram
    participant Admin
    participant web
    participant Game
    participant MySQL
    participant AI

    Admin->>web: 创建手牌，提交 drill_id、title
    web->>Game: 转发创建手牌请求
    Game->>AI: 校验 drill_id 是否可用
    AI-->>Game: 返回校验结果
    Game->>MySQL: 写入 duplicate_match_hand
    MySQL-->>Game: 写入成功
    Game-->>web: 返回 hand_id
    web-->>Admin: 返回创建结果
```

关键说明：

```text
手牌通过 drill_id 关联已有 drill 玩法。
duplicate_match_hand 不复制 drill 内部数据。
```

### 3.2.4 后台角度接口时序图：创建活动

```mermaid
sequenceDiagram
    participant Admin
    participant web
    participant Game
    participant MySQL

    Admin->>web: 创建活动，提交 hand_pack_id、play_hand_count、start_time、end_time
    web->>Game: 转发创建活动请求
```

关键说明：

```text
play_hand_count 来自后台配置，不能写死。
活动创建后默认 draft。
```

### 3.2.6 用户角度接口时序图：进入活动 / 恢复进度

```mermaid
sequenceDiagram
    participant client
    participant web
    participant Game
    participant MySQL

    client->>web: 进入活动页 / resume(activity_id)
    web->>Game: 转发 resume 请求
    Game->>MySQL: 查询 activity
    Game->>MySQL: 查询 user_entry
    Game->>MySQL: 查询 user_hand
    Game->>MySQL: 查询 leaderboard_result
    MySQL-->>Game: 返回活动进度数据
    Game-->>web: 返回当前状态和下一步动作
    web-->>client: 返回页面状态
```

返回状态示例：

| 状态           | 前端动作          |
| ------------ | ------------- |
| `not_joined` | 展示开始挑战        |
| `playing`    | 展示继续挑战        |
| `completed`  | 展示当前榜 / 最终榜入口 |
| `expired`    | 展示已截止         |

关键说明：

```text
恢复的是活动进度。
不恢复单手中途牌局状态。
```

### 3.2.7 用户角度接口时序图：参加活动 / 分配手牌

```mermaid
sequenceDiagram
    participant client
    participant web
    participant Game
    participant MySQL

    client->>web: join(activity_id)
    web->>Game: 转发 join 请求
    Game->>MySQL: 查询活动配置
    Game->>MySQL: 查询是否已有 entry

    alt 已参赛
        MySQL-->>Game: 返回已有 entry 和 user_hand
        Game-->>web: 返回已有参赛进度
        web-->>client: 返回已有参赛进度
    else 未参赛
        Game->>MySQL: 开启事务
        Game->>MySQL: 写入 duplicate_match_user_entry
        Game->>MySQL: 按 play_hand_count 分配 N 手牌
        Game->>MySQL: 批量写入 duplicate_match_user_hand
        Game->>MySQL: 提交事务
        Game-->>web: 返回参赛成功和第一手信息
        web-->>client: 返回参赛成功和第一手信息
    end
```

关键说明：

```text
join 需要幂等。
手牌分配结果写入 MySQL 后固定不变。
```

### 3.2.9 用户角度接口时序图：提交每手结果

```mermaid
sequenceDiagram
    participant client
    participant web
    participant Game
    participant MySQL
    participant Redis

    client->>web: submitHand(user_hand_id, pve_result)
    web->>Game: 转发 submitHand 请求
    Game->>MySQL: 查询 user_hand / entry / activity
    Game->>MySQL: 校验当前手是否可提交
    Game->>Game: 生成 raw_result、win_loss_bb、score

    Game->>MySQL: 开启事务
    Game->>MySQL: 写入 duplicate_match_hand_score
    Game->>MySQL: 更新 user_hand.status=completed
    Game->>MySQL: 更新 entry 完成手数和总分

    alt 已完成 N 手
        Game->>MySQL: 写入 duplicate_match_leaderboard_result
    end

    Game->>MySQL: 提交事务
    Game->>Redis: 事务提交后失效 / 更新榜单缓存
    Game-->>web: 返回本手结果和下一步动作
    web-->>client: 返回本手结果和下一步动作
```

关键说明：

```text
submit hand 需要幂等。
最后一手完成时，同事务写 score、entry、leaderboard_result。
Redis 必须在 MySQL 事务提交后处理。
```

### 3.2.10 用户角度接口时序图：完成 N 手后查看当前榜

```mermaid
sequenceDiagram
    participant client
    participant web
    participant Game
    participant Redis
    participant MySQL

    client->>web: 查询当前榜 activity_id
    web->>Game: 转发当前榜查询
    Game->>Redis: 查询当前榜分页缓存

    alt Redis 命中
        Redis-->>Game: 返回缓存榜单
    else Redis 未命中
        Game->>Redis: 获取短锁 / singleflight
        Game->>MySQL: 查询 leaderboard_result 动态排序
        Game->>Redis: 写入分页缓存
    end

    Game-->>web: 返回当前榜
    web-->>client: 返回当前榜
```

关键说明：

```text
当前榜只展示完成 N 手的用户。
排序：total_score DESC, complete_time ASC。
```

### 3.2.11 用户角度接口时序图：活动结算后查看最终榜

```mermaid
sequenceDiagram
```

### 3.2.12 用户角度接口时序图：断线 / 刷新 / 换设备恢复

```mermaid
sequenceDiagram
    participant client
    participant web
    participant Game
    participant MySQL

    client->>web: resume(activity_id)
    web->>Game: 转发 resume 请求
    Game->>MySQL: 查询 activity
    Game->>MySQL: 查询 user_entry
    Game->>MySQL: 查询 user_hand
    Game->>MySQL: 查询 hand_score / leaderboard_result
    Game-->>web: 返回恢复状态
    web-->>client: 返回恢复状态
```

恢复规则：

| 状态        | 处理        |
| --------- | --------- |
| 未参赛       | 返回开始挑战    |
| 已参赛未完成    | 返回当前应继续手牌 |
| 当前手已完成    | 返回下一手     |
| 已完成 N 手   | 返回榜单入口    |
| 活动已截止且未完成 | 不允许继续挑战   |

关键说明：

```text
只恢复活动进度。
不恢复单手中途状态。
```

### 3.2.13 Worker 角度时序图：活动截止后最终榜结算

```mermaid
sequenceDiagram
    participant Worker
    participant Redis
    participant MySQL

    Worker->>MySQL: 扫描已截止且未 finalized 的活动
    Worker->>Redis: 获取 activity_id 结算锁

    alt 获取锁失败
        Worker-->>Worker: 跳过本次结算
    else 获取锁成功
        Worker->>MySQL: 查询完成 N 手的 entry / leaderboard_result
        Worker->>MySQL: 按 total_score DESC, complete_time ASC 排序
        Worker->>MySQL: 写入 rank_no、is_final、finalized_at
        Worker->>MySQL: 更新 activity.status=finalized
        Worker->>Redis: 删除 / 刷新榜单缓存
        Worker->>Redis: 释放结算锁
    end
```

关键说明：

```text
Worker 通过 Redis 结算锁避免重复结算。
最终榜以 MySQL 写入结果为准。
Worker 重复执行需要幂等。
```
