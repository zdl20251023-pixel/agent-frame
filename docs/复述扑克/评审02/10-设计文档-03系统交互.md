# 三、系统交互

## 3.1 是否有新增服务器

无。

本需求不新增独立服务器，复用当前已有链路，在现有系统上新增复式扑克 PvE 排名赛相关能力。

| 模块       | 说明                                          |
| -------- | ------------------------------------------- |
| `client` | 用户端 / 管理后台前端，负责活动查看、参赛、打牌、查榜，以及后台配置入口       |
| `Admin`  | 管理后台服务，负责活动及手牌配置，直接操作 MySQL               |
| `web`    | 无状态 Web 层，负责用户活动业务编排、进度查询、榜单查询             |
| `Game`   | 有状态游戏服务，负责具体 drill 对局运行及单局结束后的输赢落库         |
| `MySQL`  | 比赛事实源，保存活动、参赛、手牌分配记录数据                      |
| `Redis`  | 保存N手完成临时结果、实现以输赢BB数为准的排行榜、活动结算锁             |

## 3.2 是否有 CS 交互，SS 交互

有。

| 类型            | 说明                                             |
| ------------- | ---------------------------------------------- |
| 管理后台交互        | `client -> Admin -> MySQL`                     |
| 用户端 CS 交互     | `client -> web`                                |
| web 与 Game 交互 | `web -> Game`，用于创建排名赛 drill 对局、转发牌桌操作、获取牌桌状态   |
| DB 交互         | `Admin / web / Game -> MySQL / Redis`          |

时序图标记说明：

```text
->>  尖角实线：异步请求 / 异步返回
-->> 虚线：同步请求 / 同步返回
-)   圆角实线：快速跳过步骤，用于表示本图不展开的简化流程
```

### 3.2.1 系统交互总览：以 N=2 为例

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant Admin
    participant web
    participant Game
    participant MySQL
    participant Redis

    client->>Admin: 后台配置手牌与活动
    Admin-->>MySQL: 写入 hand、activity
    MySQL-->>Admin: 返回配置结果
    Admin->>client: 返回后台配置结果

    client->>web: get_activity_list
    web-->>MySQL: 查询已发布活动和用户参赛状态
    MySQL-->>web: 返回活动列表和参赛状态
    web->>client: 返回活动列表

    client->>web: join_activity(activity_id)
    web-->>MySQL: 写入 user_entry，并分配 2 手牌写入 user_hand_record
    MySQL-->>web: 返回基础参赛信息
    web->>client: 返回基础参赛信息

    client->>web: resume_activity(activity_id)
    web-->>MySQL: 查询用户活动进度
    MySQL-->>web: 返回当前应开始的手牌
    web->>client: 返回当前应开始的手牌

    loop 每手牌，直到完成 N 手
        client->>web: start_hand(user_hand_record_id)
        Note over web, MySQL: 减少查表，直接校验进度并取 drill_info
        web-->>MySQL: 校验进度，读取 hand.drill_info，更新 user_hand_record=playing
        web->>Game: 直接创建排名赛 drill 对局
        Game->>web: 返回 table_info
        web->>client: 返回 table_info (前端直接进桌)

        client->>web: 进行牌桌操作
        web->>Game: 转发牌桌操作

        alt 牌局未结束
            Game->>web: 返回牌桌进行中状态
            web->>client: 返回牌桌进行中状态
        else 牌局结束 (自动结算)
            Note over Game, MySQL: 取消 submit_hand，游戏服直接写库结算
            Game-->>MySQL: 更新 user_hand_record (写入 win_loss_bb，状态改为 completed)
            Game-->>MySQL: 更新 user_entry (累加已完成手数与总输赢 BB 数)
            
            alt 已完成 N 手
                Game-->>Redis: 将总输赢 BB 数写入活动对应的 Sorted Set
            end
            
            Game->>web: 返回牌桌结束状态
            web->>client: 返回牌桌结束状态
        end

        client->>web: resume_activity(activity_id)
        web-->>MySQL: 查询最新活动进度
        MySQL-->>web: 返回下一手或榜单入口
        web->>client: 返回下一手或榜单入口
    end

    client->>web: get_current_leaderboard(activity_id)
    web-->>Redis: 查询当前榜 Sorted Set (总输赢 BB 数)
    Redis-->>web: 返回当前榜
    web->>client: 返回当前榜
```

关键说明：

```text
submit_hand 流程被取消。
单局结束后，由 Game 服务器直接更新 MySQL 中的对局记录 (user_hand_record) 和参赛总表 (user_entry)。
排行榜无 MySQL 表，达到完成条件时直接写 Redis Sorted Set。
Worker 结算本期暂不实现。
```

### 3.2.2 后台角度接口时序图：配置活动

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant Admin
    participant MySQL

    client->>Admin: create_hand，提交 drill_info、title
    Admin-->>MySQL: 写入 duplicate_match_hand
    MySQL-->>Admin: 返回 hand_id
    Admin->>client: 返回手牌创建结果

    client->>Admin: create_activity (包含绑定的 handList)
    Admin-->>MySQL: 校验 play_hand_count、start_time、end_time
    Admin-->>MySQL: 写入 duplicate_match_activity，status=draft
    MySQL-->>Admin: 返回 activity_id
    Admin->>client: 返回活动创建结果

    client->>Admin: publish_activity
    Admin-->>MySQL: 校验活动配置完整性
    Admin-->>MySQL: 更新 activity.status=published
    MySQL-->>Admin: 返回发布结果
    Admin->>client: 返回发布成功
```

关键说明：

```text
取消了 pack 牌局包概念，活动创建时直接在 handList(JSON) 中配置手牌集合。
duplicate_match_hand 保存 drill_info，开始牌局时直接通过配置启动 drill。
```

```mermaid
sequenceDiagram

    participant MySQL
```

```mermaid
        web-->>MySQL: 提交事务
        MySQL-->>web: 返回基础参赛信息
        web->>client: 返回基础参赛信息
    end
```

### 3.2.7 用户角度接口时序图：进行牌局与自动结算

```mermaid
sequenceDiagram
    autonumber
    participant client
    participant web
    participant Game
    participant MySQL
    participant Redis

    client->>web: 牌桌操作 (携带 table_id)
    web->>Game: 转发牌桌操作

    alt 牌局未结束
        Game->>web: 返回牌桌进行中状态
        web->>client: 返回牌桌进行中状态
    else 牌局结束
        Game-->>MySQL: 开启事务
        Game-->>MySQL: 更新 duplicate_match_user_hand_record (写入 win_loss_bb，设为 completed)
        Game-->>MySQL: 更新 duplicate_match_user_entry (累加 BB 和 completed_hand_count)
        Game-->>MySQL: 提交事务
        
        alt 累加后已完成 N 手
            Game-->>Redis: 将总输赢 BB 写入 Redis Sorted Set
        end
        
        Game->>web: 返回牌桌结束状态
        web->>client: 收到牌桌结束，主动调用 resume_activity 推进下一步
    end
```

关键说明：

```text
取代了原先的 `submit_hand`，由 Game 服务端直接落地结果，杜绝作弊和并发问题。
```
